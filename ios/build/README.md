# tools/ios/build - Build Utilities

Scripts for build automation, code quality, and development workflows.

## Overview

This folder contains 3 scripts that support the build process and development workflows:
1. Fastlane automation wrapper
2. SwiftLint code quality checks
3. Download script configuration updates

## Scripts

### fastlane_run.sh

Wrapper script for executing Fastlane commands with proper environment setup.

**Usage:**
```bash
./fastlane_run.sh [fastlane_command] [arguments...]
```

**Examples:**
```bash
# Generate screenshots
./fastlane_run.sh ios screenshots

# Add device frames
./fastlane_run.sh ios add_frames

# Upload to App Store Connect
./fastlane_run.sh ios upload_screenshots

# Custom lane
./fastlane_run.sh ios custom_lane --env production
```

**Features:**
- Environment variable setup
- Ruby version management
- Bundler dependency resolution
- Error handling and logging

**When to use:**
- Running Fastlane lanes from scripts
- CI/CD pipeline integration
- Automated screenshot generation
- App Store Connect uploads

**Requirements:**
- Ruby (via Homebrew or system)
- Bundler gem
- Fastlane configured (see `tools/ios/fastlane/Fastfile`)

### swiftlint.sh

Run SwiftLint code quality checks on the project.

**Usage:**
```bash
# Run SwiftLint on entire project
./swiftlint.sh

# Run with autocorrect
./swiftlint.sh --fix

# Run on specific paths
./swiftlint.sh --path Deddal/Models
```

**Features:**
- Code style enforcement
- Swift best practices validation
- Automatic fixes for common issues
- Custom rule configuration

**SwiftLint rules location:**
- `.swiftlint.yml` (project root)

**Common violations:**
- Line length (120 characters max)
- Force unwrapping (avoid `!`)
- Trailing whitespace
- Unused variables
- Naming conventions

**When to use:**
- Before committing code changes
- CI/CD pipeline validation
- Code review preparation
- Onboarding new developers (learn conventions)

**Integration options:**

**Pre-commit hook:**
```bash
# .git/hooks/pre-commit
#!/bin/bash
./tools/ios/build/swiftlint.sh
if [ $? -ne 0 ]; then
    echo "SwiftLint failed. Commit aborted."
    exit 1
fi
```

**Xcode build phase:**
Add to Build Phases → Run Script:
```bash
if [ -f ./tools/ios/build/swiftlint.sh ]; then
    ./tools/ios/build/swiftlint.sh
fi
```

### update_download_scripts.sh

Update configuration for VisualCube API download scripts.

**Usage:**
```bash
./update_download_scripts.sh
```

**What it updates:**
- VisualCube API endpoints
- Download script parameters (size, format, view)
- Case code mappings
- Output directory paths

**When to use:**
- VisualCube API changes
- Adding new case types
- Changing image format/size requirements
- Bulk script configuration updates

**Affects scripts in:**
- `tools/shared/assets/download/` (8 download scripts)

**Example updates:**
- Change image size from 200x200 to 300x300
- Update API base URL
- Add new query parameters
- Modify output directory structure

## SwiftLint Configuration

The project uses `.swiftlint.yml` for configuration:

```yaml
# Example rules (see actual file for current config)
line_length: 120
identifier_name:
  min_length: 2
  max_length: 60
force_unwrapping: error
trailing_whitespace: warning

excluded:
  - Pods
  - build
  - DerivedData
```

**Key rules:**
- **Line length**: Max 120 characters
- **Force unwrapping**: Error (use optional binding)
- **Trailing whitespace**: Warning
- **Naming**: camelCase for variables, PascalCase for types

## Troubleshooting

### fastlane_run.sh Issues

**Ruby version mismatch:**
```bash
# Check Ruby version
ruby --version

# Install correct version via Homebrew
brew install ruby@3.4

# Update PATH
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
```

**Bundler not found:**
```bash
gem install bundler
bundle install
```

**Fastlane gem errors:**
```bash
bundle update fastlane
bundle install
```

### swiftlint.sh Issues

**SwiftLint not installed:**
```bash
brew install swiftlint
```

**Config file not found:**
- Ensure `.swiftlint.yml` exists in project root
- Check file permissions

**Too many warnings:**
- Start with `--fix` to auto-correct
- Gradually address remaining issues
- Disable rules temporarily if needed (not recommended)

### update_download_scripts.sh Issues

**Scripts not updated:**
- Check file permissions
- Verify paths to download scripts
- Review sed/awk syntax in script

**Download failures after update:**
- Test VisualCube API manually
- Verify updated parameters are correct
- Check API endpoint accessibility
